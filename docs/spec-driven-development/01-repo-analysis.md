# 01. 面向 SDD 的仓库分析（openGemini）

## 1. 基线信息

- 模块：`github.com/openGemini/openGemini`（`go.mod`）。
- 语言版本：Go `1.24`。
- 构建入口：`python build.py`、`Makefile`。
- 代码规模：`go list ./...` 可枚举约 175 个包（受网络环境影响可能出现依赖下载警告）。

## 2. 架构分层与规格边界

### 2.1 应用入口与进程编排（`app/`）

- 典型入口：`ts-meta`、`ts-store`、`ts-sql`。
- 本地一体化绑定：`app/ts-server/run/run.go` 将 SQL 读写链路连接到本地 Store。

**SDD 边界建议**

- 涉及节点角色、启动参数、进程编排改动，必须在 Feature Spec 中给出部署影响。
- 涉及入口 wiring（依赖注入）变更，必须在 Technical Design 标注控制流变化。

### 2.2 协调层（`coordinator/`）

职责：写入/查询请求编排、跨节点路由与失败处理。

**SDD 边界建议**

- 必须显式定义失败语义：重试次数、超时、幂等性、降级行为。
- 必须说明对上层（SQL）和下层（Engine/Store）的契约不变量。

### 2.3 引擎层（`engine/`）

- 子域：`mutable`（写入态）、`immutable`（持久化态）、`index`、`executor/hybridqp/optimizer`。

**SDD 边界建议（强制）**

1. 读写路径影响图；
2. 资源预算（CPU/内存/磁盘）；
3. 查询计划/索引耦合点；
4. 回滚路径（配置开关或版本回退）。

### 2.4 服务层（`services/`）

职责：保留策略、分层、写服务、管理能力。

**SDD 边界建议**

- 必须附运维可观测要求：新增 metrics、日志字段、告警规则。
- 必须声明是否影响默认行为与线上参数。

### 2.5 基础库（`lib/`）

职责：公共能力（编码压缩、配置、网络、缓存、观测、对象存储等）。

**SDD 边界建议**

- 将 `lib/` 变更视作高扇出影响，Task Plan 必须附带“受影响包回归清单”。

## 3. 质量与验证基线

最小命令集（按改动范围挑选）：

- `git diff --check`
- `make gotest`
- `make integration-test`（协议/跨模块变更时）
- `make style-check`
- `make go-vet-check`
- `make static-check`

## 4. AI 自动编码风险地图

1. **跨层隐式耦合**：入口 wiring 与执行链路可能被误改。
2. **性能漂移**：关键路径微小改动导致 P99 放大。
3. **兼容回退**：协议行为或默认配置变更引发客户端失败。
4. **可观测缺失**：功能实现完成但缺指标/日志，线上不可运营。

## 5. 变更分级与审查强度

- **P0**：`engine` 关键路径、索引、执行器。
  - 要求：双评审 + 性能对比 + 回滚演练。
- **P1**：`coordinator/services` 逻辑改造、跨模块配置变更。
  - 要求：模块 Owner 评审 + 集成场景验证。
- **P2**：文档、局部工具、测试辅助。
  - 要求：常规评审。

## 6. 定义完成（DoD）建议

每个功能合并前至少满足：

- [ ] Spec/Design/Task/Acceptance 四件套齐全。
- [ ] 每个代码改动均可映射到 `FS-x` 或 `TD-x`。
- [ ] 每条验收标准均有测试证据（命令或日志）。
- [ ] 发布与回滚步骤可执行。
